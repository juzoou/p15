# Пятнашки 2026 — алгоритмы решения (задача 4 из плана)

Набор решателей на C++17. Каждый алгоритм — отдельная программа с интерфейсом из
плана: два аргумента (файл задачи и путь для решения), в стандартный вывод
печатается значение целевой функции F, в файл — решение в формате
DATA / COST / ORDER из презентации.

| Программа    | Идея                                                                 | Где сильнее всего |
|--------------|----------------------------------------------------------------------|-------------------|
| `p15_exact`  | Дейкстра по всем позициям, максимум F (с частичными решениями)       | поля до 10 клеток — доказанный оптимум |
| `p15_ida`    | IDA* «ветви и границы» по F, аддитивные БД образцов                  | поля до ~4×4, 3×5, а также позиции любого размера, близкие к собранной — доказанный оптимум |
| `p15_reduce` | послойная сборка (строка/столбец) с оптимальной проводкой фишек с учётом стоимостей | быстрый надёжный базовый вариант для любых полей, где полная сборка выгодна |
| `p15_beam`   | лучевой поиск: целиком (до 6×6) или послойно с «полезными» переходами пустой | средние поля 5×5 … ~40×40 — сборка на 20–40 % дешевле, чем у reduce |
| `p15_greedy` | частичная сборка: ставит только выгодные фишки                       | большие поля (от ~50×50), где полная сборка стоит дороже, чем приносит |
| `p15_best`   | портфель: делит время между подходящими алгоритмами и берёт лучший результат | для соревнования |

## Сборка

Нужен компилятор C++17 (g++ ≥ 7, clang, MSVC 2017+).

```sh
./build.sh                      # Linux / macOS / MinGW, бинарники в bin/
build.bat                       # Windows (cl из Developer Command Prompt или g++)
cmake -B build && cmake --build build --config Release   # либо через CMake
```

## Запуск

```sh
bin/p15_reduce задача.txt решение.txt            # печатает F
bin/p15_best   задача.txt решение.txt --time 120 # ограничение времени, с
bin/p15_beam   задача.txt решение.txt -v         # журнал работы в stderr
```

* Перед решением проверяется, что в файл решения можно писать (если нельзя — код 3).
* В stdout выводится только число F; диагностика — в stderr.
* Время: `--time T` (секунды). По умолчанию: ida 30, reduce 10, beam 30, greedy 30,
  best 60; exact работает без ограничения. Алгоритмы «anytime»: чем больше
  времени, тем лучше результат (beam расширяет луч, reduce перебирает стратегии,
  ida продолжает поиск). Лимит соблюдается с точностью до пары секунд (на больших
  полях — финальная проверка и обработка последовательности).
* Коды возврата: 0 — решение записано; 1 — неверные аргументы; 2 — ошибка во входном
  файле; 3 — нельзя записать решение; 4 — внутренняя ошибка / нехватка памяти;
  5 — алгоритм не применим к задаче (exact на большом поле); 6 — в режиме проверки
  ORDER содержит недопустимый ход.

### Форматы входа

Формат определяется автоматически.

1. **Формат презентации** (ключевые слова DATA, SIZE, COST, ORDER, `--` комментарии,
   `=` — пустая клетка, `/` — конец блока). SIZE задаёт *строки, столбцы*.
   Если COST нет — все стоимости 1.
2. **Упрощённый формат из плана**: целые числа через пробелы —
   `cU cD cL cR w h a1 … a(w·h)`, где `w` — ширина (столбцы), `h` — высота (строки),
   фишки построчно, 0 — пустая клетка. Порядок стоимостей U D L R взят из
   презентации.

Если во входе есть блок ORDER, программа работает во **втором режиме** из
презентации: проверяет ходы (ошибки — с номером хода, нумерация с единицы) и
считает F. Например, `tests/samples/t10.txt` даёт 599.

Ошибки формата (нет DATA, не хватает строк, лишние числа в строке, повтор фишки…)
сообщаются в stderr с номером строки, код возврата 2. Отсутствие завершающего `/`
считается предупреждением (с ключом `--strict` — ошибкой).

### Выход

Файл решения: комментарии с итогом (`-- F = ...`), затем DATA, COST и ORDER в
формате презентации. Ходы записываются как «номер фишки + направление её движения».

**Неразрешимые позиции.** Если конечное расположение недостижимо (нечётная
перестановка), в файл пишется комментарий `-- NO SOLUTION: ...`, в stderr —
`UNSOLVABLE`, а ORDER всё равно содержит последовательность, максимизирующую F
(обычно на местах оказываются все фишки, кроме одной–двух). Если нужен только
факт неразрешимости, достаточно проверить эту строку.

## Целевая функция и «лучший префикс»

F = 100·P − Σ Cd·Nd, где P — число фишек на своих местах **после последнего хода**.
Поэтому собирать поле целиком не обязательно: если доставить фишку дороже 100,
выгоднее её не трогать. Все алгоритмы это учитывают, а общая пост-обработка:

* удаляет циклы (повторы позиций) из последовательности ходов;
* обрезает её до префикса с максимальным F (в т. ч. до пустого — F не бывает хуже,
  чем у «ничего не делать»).

Итоговая последовательность каждый раз заново проверяется симуляцией.

## Алгоритмы подробнее

### exact
Дейкстра по всему пространству позиций (перестановки кодируются кодом Лемера).
Находит максимум F по всем достижимым позициям, поэтому оптимален и для
неразрешимых задач, и для случаев, когда выгодна частичная сборка. До 10 клеток
(3×3, 2×5: ≤ 1,8 млн позиций); на больших полях завершается с кодом 5.

### ida
IDA* в форме ветвей и границ по F. Верхняя граница для узла:
* для собранной позиции — 100·K − h, где h = max(взвешенное манхэттенское
  расстояние + линейные конфликты, аддитивные БД образцов 5-5-5);
* для позиций, где не на месте хотя бы одна фишка — Σ max(0, 100 − md_t) минус
  наименьшее слагаемое (стоимости учитываются в md_t).

БД образцов строятся при запуске под конкретные стоимости (для полей до 25
клеток). Для неразрешимых задач перебираются цели «все на местах, кроме X»
(X — в углу), это даёт точный оптимум и здесь. Есть таблица транспозиций и
адаптивный порог итераций. Если поиск завершился, решение оптимально (в журнале
`-v` — «OPTIMAL»). Начальный рекорд (для полей до 400 клеток) берётся из быстрого
reduce, поэтому на средних полях ida не хуже reduce, но доказать оптимальность
там уже не удаётся.

### reduce
Послойная сборка: верхняя строка или левый столбец текущего прямоугольника.
* Каждая фишка проводится оптимальным по стоимости путём: A* по состояниям
  «клетка фишки + сторона, где пустая», переходы «сдвиг фишки» и «обход пустой
  вокруг фишки» с учётом стоимостей направлений и уже собранных клеток.
* Две последние клетки линии — точный поиск в окне (до 4×3 клеток) по состояниям
  (фишка a, фишка b, пустая), без ручных «спецслучаев».
* Остаток ≤ 9 клеток — exact; если время осталось, последний фрагмент ≤ 16 клеток
  пересобирается алгоритмом ida.
* Перебираются стратегии выбора «строка/столбец» и направления заполнения
  (в т. ч. пробный выбор по стоимости на фишку и случайные варианты), берётся лучшая.
* Ранний выход, если даже идеальное продолжение не догонит рекорд.

### beam
Лучевой поиск по ходам пустой клетки, ширина растёт пока есть время.
* Поля до 6×6 — по всему полю: f = g + h, h — взвешенное манхэттенское расстояние
  с линейными конфликтами, веса фишек выше у «ранних» слоёв.
* Больше — послойно, как reduce, но каждая строка/столбец собирается лучевым поиском
  сразу для всех её фишек. Эвристика этапа: фишки линии — (стоимость хода + 3 средних
  стоимости) за шаг; остальные фишки области — со весом 1 (поэтому переходы пустой
  клетки заодно подтягивают и другие фишки); путь пустой до клетки, откуда толкать
  очередную фишку, и до следующих; штраф за фишку, поставленную не по порядку
  (иначе образуются «карманы»). Пара в конце линии — точным поиском, остаток ≤ 25
  клеток — глобальным лучевым поиском (≤ 16 клеток — ещё и ida). Если этап не
  сошёлся, берётся лучший частичный результат и дособирается по одной фишке.

### greedy
Для больших полей, где полная сборка убыточна (например, на 100×100 она требует
порядка миллиона ходов при ценности ~10⁶). Повторяет: быстрая оценка кандидатов
(α·расстояние + путь пустой) → точная стоимость проводки → выбор максимальной
прибыли 100 − стоимость (с учётом того, как маршрут сдвигает другие фишки) →
проводка и фиксация фишки. Фиксация не должна разрывать свободную область и
создавать тупики. Уже стоящие на местах фишки фиксируются сразу.

### best
Портфель, время делится между алгоритмами, берётся лучший результат:
* ≤ 10 клеток — exact;
* позиция близка к собранной (мало фишек не на местах или малое суммарное
  расстояние) — ida, затем reduce и beam;
* ≤ 25 клеток — reduce → beam → ida (с рекордом beam, часто доказывает оптимум) → beam;
* до 2500 клеток — greedy (один быстрый прогон: при дорогих ходах частичная сборка
  бывает выгоднее полной), reduce, beam (основное время); рекорд передаётся дальше,
  и заведомо убыточная полная сборка прерывается;
* больше — greedy.

* **5×5 … 30×30** лучший — beam: на 3–95 % больше F, чем у reduce; разрыв растёт с

* **позиции, близкие к собранной** — ida (часто с доказанным оптимумом), на очень
  больших полях — beam/reduce;
* **от ~50×50** полная сборка убыточна, выигрывает только greedy (частичная сборка).
  Граница зависит от времени: на 40×40 beam за ~90 с собирает поле целиком и
  получает F = 45 247 (greedy — 16 150); на 50×50 полная сборка даже у beam стоит
  ≈ ценности поля, greedy — 20 788; на 60×60 greedy — 25 068;
* **best** почти везде равен лучшему, но при коротком лимите делит время и иногда
  немного уступает «чемпиону» (20×20 c3111). На соревновании ему стоит давать
  больше времени: beam и ida улучшают результат с ростом лимита.

Пример из слайда «Постановка задачи» (`5 1 3 7 / 4 2 = 6`) на самом деле
**неразрешим** (чётная перестановка при нечётном расстоянии пустой клетки до угла);
оптимум exact — F = 585: 6 из 7 фишек на местах за 15 ходов
(`tests/samples/example_2x4.txt`).

## Параметры алгоритмов (для экспериментов)

Передаются как `--имя значение`:

* reduce: `--runs N` (число прогонов), `--exact-cells 9`, `--ida-endgame 0/1`;
* ida: `--pdb-k 5` (размер группы БД образцов, 0 — без БД), `--tt-bits 21`, `--warm 0/1`;
* beam: `--width W` (фиксированная ширина), `--staged 0/1`, `--kappa-goal 3`,
  `--omega-rest 1`, `--beta 1`, `--tau 5`, `--end-cells 25`, `--lambda`, `--w`;
* greedy: `--alpha 3`, `--cand 12`, `--by-cands 4`, `--by-weight 0.5`, `--kappa 4`;
* exact: `--exact-max-cells 10`.

* `t10.txt` … `t15.txt` — присланные примеры: t10 — режим проверки ORDER (F = 599),
  t11 — нет DATA, t12 — нет завершающего `/` (предупреждение, решается), t13 — не

  находят те же 2 хода);
* `example_2x4.txt`, `example_2x4_simple.txt` — пример со слайда «Постановка задачи»
  в обоих форматах (неразрешим, F = 585).

## Инструменты (`tools/`)

* `gen.py` — генератор задач: случайные (половина неразрешима), только разрешимые,
  `walkL` — L случайных ходов от собранного поля; оба формата.
* `check.py` — независимая проверка файла решения и пересчёт F.
* `bench.py` — прогон нескольких решателей по папке задач с проверкой каждого
  решения, таблица F и `results.csv` (это упрощённый вариант задачи 3 — для отладки);
* `table.py` — сводная markdown-таблица по одному или нескольким `results.csv`.

```sh
python3 tools/gen.py tests/gen --sizes 4x4,10x10 --kinds random,walk50 --costs 1111,3111
python3 tools/bench.py tests/gen out --algos reduce,beam,best --time 10
```
