# p15_lns — послойная сборка с потенциальной проводкой + LNS по пути

Решатель в стиле ваших файлов: использует ваш `parser.h/.cpp` без изменений, формат вывода
как в вашем `write_output` (DATA / COST / ORDER). Не зависит от `astar.h` / `builder.h`
(свой тип хода `LnsMove`, чтобы не конфликтовать с `Move`).

    sh build.sh
    ./p15_lns вход.txt выход.txt [секунды=30] [-v]     # stdout: F

Вход: ваш формат (4 цены, rows cols, клетки) либо формат презентации (DATA/SIZE/COST).
Неразрешимые позиции: пишется лучшая достижимая расстановка, в stderr — предупреждение.
Подключение к своему main: `solve_lns(rows, cols, weights, cells, time_limit)` из `lns.h`.

## Алгоритм (не лучевой поиск, не IDA*, не reduce из репозитория)

1. **Сборка по слоям внутри bounding box сдвинутых клеток** (всё снаружи заблокировано, поэтому
   почти собранные поля дёшевы). Фишка проводится A*-ом по состояниям «клетка фишки + сторона пустой»
   с точными ценами направлений; последние две клетки линии — точный поиск в окне 3×2;
   хвост ≤3×3 (и целиком поля ≤10 клеток) — Дейкстра с максимизацией F, поэтому неразрешимые
   позиции обрабатываются без спецслучаев.
2. **Потенциальная поправка пути пустой клетки (λ).** Ребро пустой клетки получает цену
   `cost + λ·Δφ`, где Δφ — изменение взвешенного расстояния чужой фишки до её цели. Ход пустой
   клетки становится полезным сразу для нескольких фишек. Мультистарт по λ ∈ {0…0.9}, берётся лучший.
   Это главный источник выигрыша (15×15: 14483 → 16583).
3. **Режим «жертвования»** для больших полей: фишка, проводка которой дороже 100, остаётся как есть
   (клетка блокируется).
4. **LNS по последовательности ходов** (память O(длина пути)): (а) окна — между состояниями S_i и S_j
   точный A* по разреженному состоянию с лимитом узлов; (б) обходы — ограниченный DFS из каждого
   состояния пути, совпадение с позднейшим состоянием по хешу Зобриста; затем удаление циклов и
   обрезка до префикса с максимальным F.

Память ограничена (десятки МБ на 100×100), время — аргументом.

## Результаты (20 с, 2 ядра; репозиторий — `p15_best`, 20 с)
| задача | p15_lns | repo best |
|---|---:|---:|
| 4×4 / 5×5 / 8×8 random | −1…−7 % | |
| 15×15 random c1111 | 16787 | 17631 |
| 30×30 random c1111 | 41862 / 43485 | 32446 / 38463 |
| 89×98, 600 шагов (ваш zip) | 862304 | 856553 (лучший в zip: 856796) |
| walk 60×59, 3000 шагов | 336834 | 287734 |
| walk 89×98, 5000 шагов | 833210 | 746362 |
| walk 100×99, 20000 шагов (3111) | 665642 | 477771 |

Слабые места: большие полностью случайные поля (60×60, 100×100) и тяжёлые цены — там репозиторный
`greedy` лучше (послойный порядок не позволяет выбирать самые дешёвые фишки); очень почти собранные
поля — `beam` репозитория на 0,5–1 % выше. Все решения проверены `tools/check.py` (336 краевых
тестов + набор бенчмарков, расхождений нет; поля ≤10 клеток совпадают с `p15_exact`).
