# Historical development plan

This is the original README, retained as historical context. Current behavior is documented in USAGE.md.

#### Проблемы:

1. А* требует слишком много оперативной памяти и работает слишком медленно - решает не больше 3х4
2. Метод человеческого решения (с последовательным решением рядов) не учитывает ни веса по направлениям, ни общее состояние доски - низкое качество решения

#### Решение

Необходимо найти алгоритм, который бы:
- Находил решение за разумное время / ресурс компьютера
- Находил решение более оптимальное, чем у других групп

Как вариант найти несколько алгоритмов и выбрать лучший. Или выбирать лучшее решение из найденных разными алгоритмами непосредственно на соревновании. 

В любом случае для этого придется написать и сравнить реализации нескольких алгоритмов. 

#### Полный список задач:

1. Сформировать данные для тестирования: входные данные (желательно придумать способ создавать такие данные с известным оптимальным решением) для досок разных размеров в количестве не менее на 10 каждый. Думаю, для этого лучше всего сделать  специальный скрипт. 
2. Сделать скрипт для проверки решения (data + order из документа Васекина). По большому счету возвращает только true/false.
3. Сделать скрипт для оценки алгоритма решения. Формат и назначение будет описано ниже. 
4. Написать несколько алгоритмов решения в соответствии с описанными выше требованиями. Формат скрипта, входных данных и выходных данных будет описан ниже. 
5. Дальнейшие инструкции применимы только в случае, если удастся найти алгоритм, в достаточной мере задействующий вычислительную мощность. 
6. Оценить работу алгоритмов при помощи ранее написанного скрипта. Дополнительно оценить производительность алгоритмов на устройствах - узлах, которые будут использоваться на соревновании. 
7. Написать алгоритм распределения задач между узлами в соответствии с ранее изменённой производительностью. Алгоритм должен также отсеивать заведомо нерешаемые файлы
8. Написать программу - оркестратор для передачи входных данных и приёма ответов от узлов. 
9. Написать программу - клиента для получения входных данных, передачи их скрипту(ам) - решателю(ям), и обратной передачи ответов.
10. Необходимо чтобы эта пара была устойчива к потере связи - то есть  обнаруживала обрыв связи и пыталась её восстановить
11. Объединить узлы в сеть и проверить работоспособность системы. Думаю, для сети подойдёт tailscale.

#### Формат алгоритма решения

Алгоритм решения оформляется в отдельный скрипт, который вызывается с двумя аргументами командной строки. 

**Ввод:**
1. Путь к задаче (текст). 
2. Путь для записи решения (текст). Необходимо удостовериться, что запись по данному пути возможна, перед началом решения. 

Задача - отдельный текстовый файл в упрощённом формате (целые числа, разделённые пробелами):

- 1...4: веса по направлениям: up, down, left, right (я не помню в каком порядке)
- 5: ширина доски w
- 6: высота доски h
- 7...7+(w•h): номера пятнашек, 0 обозначает пустое место

**Вывод:** 
В стандартный вывод направляется скор (значение минимизируемой функции для найденного решения). 
В путь для записи решения сохраняется текстовый файл решения - в формате, определённом Васекиным. 

#### Скрипт для оценки решения

**Назначение:** 
Применяет один или несколько алгоритмов решения для решения набора задач. 
При этом определяется, какие размерности решаются, а какие - нет (возможно, нужно будет добавить тайм-аут). 
Стоит также учесть, что скрипт будет запускаться на windows и Linux - так что для работы с путями следует использовать специализированную библиотеку. Например, для python это `os.path`.

**Вход:** 
В аргументы командной строки скрипта направляются 3 строки: 

- Путь к директории с задачами в упрощённом формате. 
- Путь к директории для записи решений.
- Путь к файлу со списком алгоритмов для проверки.

Список алгоритмов это текстовый файл. Каждая строка - это команда запуска алгоритма решения, за исключением двух последних аргументов командной строки (путей к решению/задаче). Например:
```
solver1
python3 solver2
solver3 --depth 10
```
Скрипту для проверки будет достаточно прочитать строку из списка, приписать в конце 2 аргумента - путь к задаче и путь к решению, и выполнить полученную команду.

**Выход:**
В стандартный вывод или отдельный файл направляются данные о том, какие задачи удается решить, и за какое время.
Думаю, стоит использовать именно файл в формате csv (с результатами тестирования и отправлять в стандартный вывод прогресс тестирования. 
В директорию для решений сохраняются полученные решения. Названия файлов решений можно выбрать как <имя задачи>_<имя алгоритма>.
