# Пятнашки: интегрированный Python/C++ проект

Модульный C++17-решатель находится в `cpp/`, Python-парсер и независимая проверка — в `scripts/`.
Исходные архивы сохранены. Устаревший монолитный `pyatnashki.cpp` не включён в рабочую сборку.

## Быстрый запуск

Требуются Python 3.10+ и `g++` либо `clang++` в PATH. Внешних Python-пакетов нет.
Все команды ниже выполняются из корня репозитория на Windows или Linux.

```console
python scripts/build_cpp.py
python scripts/solve_cpp.py --algorithm auto tests/teacher/t01.txt solution.txt
python scripts/run_teacher_tests.py
python scripts/run_tests.py
```

`solve_cpp.py` при необходимости собирает программу и выводит в stdout только целочисленную оценку F.
Решение сохраняется в формате `DATA/COST/ORDER`. Ошибка выводится в stderr; код завершения — 2.
Нативный исполняемый файл находится в `build/pyatnashki_cpp.exe` на Windows и `build/pyatnashki_cpp` на Linux.
При прямом запуске он выводит подробный отчёт; `--score-only` включает числовой вывод.
Параметры можно указывать до или после двух путей INPUT OUTPUT.

```console
python generate_task.py 3 4 --steps 100 --seed 42 --costs 2 3 1 4 -o task.txt
python scripts/solve_cpp.py --algorithm linearconflict --max-expanded 1000000 task.txt solution.txt
python scripts/solve_cpp.py solution.txt checked.txt
```

Вход с `ORDER` только проверяется: программа не дополняет и не заменяет предоставленные ходы.
`CHECK: VALID` означает допустимость ходов; отдельный признак `solved` показывает, собрано ли поле.
Для неполного допустимого решения возвращается код 0 и фактическая оценка.
Пути входа и выхода должны различаться. Доступность выхода проверяется до поиска.

## Форматы

Поддерживаются оба входных формата:

1. `DATA/COST/ORDER` из задания: `SIZE строки столбцы`, пустая клетка `=`, комментарии `--`.
2. Упрощённый: `U D L R ширина высота клетки...`, пустая клетка `0`.

Тарифы задаются для движения **фишки**, а не пустоты. Отсутствующий COST означает четыре единицы.
Поддерживаются UTF-8, UTF-8 BOM и комментарии в Windows-1251 из архива преподавателя.
Windows-версия работает с кириллицей в путях.

Размеры: от 1 до 100 по каждой стороне, от 2 до 10 000 клеток.
**Квадратные поля разрешены**, поскольку тесты преподавателя включают корректные `2×2` и `3×3`.
Это осознанное изменение прежнего ограничения `N != M` из первоначального описания проекта.
На одномерном поле разрешимость определяется порядком ненулевых фишек, а пустота может быть в любом месте.

Оценка максимизируется: `F = 100 × число фишек на своих местах − стоимость ходов`.
Для полностью собранного поля максимизация F эквивалентна минимизации стоимости.

## Алгоритмы

| Параметр | Назначение |
|---|---|
| `auto` | A* до 16 клеток; на больших полях конструктивный метод по форме поля |
| `astar`, `linearconflict` | Точный поиск с эвристикой |
| `wastar --weight 1.8` | Взвешенный A*: возможна потеря оптимальности; при весе 1 обычный A* |
| `dijkstra`, `bidijkstra` | Поиск минимальной стоимости без эвристики |
| `idastar`, `rbfs` | Поиск с меньшим расходом памяти и повторными раскрытиями |
| `01bfs` | Только тарифы 0/1 |
| `dial` | Тарифы до 100 000 |
| `pdb` | Полная таблица расстояний для не более 9 клеток, только единичные тарифы |
| `annealing` | Стохастический поиск без гарантии успеха и оптимальности |
| `rowbyrow`, `columnbycolumn` | Конструктивная сборка больших полей без гарантии минимальной стоимости |
| `divideconquer` | Выбор одного из двух конструктивных методов по форме поля |

`--max-expanded` по умолчанию равен 1 000 000. Это предел раскрытий поиска, а для отжига — бюджет итераций;
он не ограничивает конструктивные методы. Тайм-аут нужно задавать внешнему запускающему процессу.
`auto` не переключается на другой метод при исчерпании лимита A*.
Отжиг использует фиксированный seed и сбрасывает путь после 500 принятых ходов.
Конструктивные методы учитывают тарифы в отчёте, но не оптимизируют по ним маршруты.
Стоимость хранится в int64; переполнение вызывает ошибку, а не некорректную оценку.

## Тесты преподавателя

`tests/teacher/t01.txt`–`t30.txt` извлечены из `tests_qual.rar` без изменения байтов.
В архиве нет эталонных ответов: ожидаемые исходы в `tests/teacher_expected.json` составлены по содержимому
задач и правилам, затем сопоставлены с C++ и независимой Python-проверкой.

```console
python scripts/run_teacher_tests.py
```

CSV сохраняется в `reports/teacher_results.csv`, решения и логи — в игнорируемом `artifacts/teacher/`.
Для ошибочных задач проверяется не только ненулевой код, но и ожидаемая причина отказа.
Для успешных — исходное поле, тарифы, сохранение ORDER, допустимость ходов, факт сборки и оценка.
`t10.txt` — корректная последовательность, оставляющая поле несобранным; ожидается F=599.
`t30.txt` — корректный формат, но неразрешимая перестановка.

Полный прогон `scripts/run_tests.py` также запускает 16 регрессионных тестов и пять исходных наборов из `cpp/tests/`.
В регрессии входят 288 сравнений с независимой Дейкстрой на `2×3`, 12 сохранённых решений из старых архивов,
одномерные поля, квадратные поля, кириллица, пустой ORDER, неверные аргументы и переполнение стоимости.

## Сборка CMake

Корневой `CMakeLists.txt` подключает `cpp/`. Для среды с настроенным генератором:

```console
cmake -S . -B build/cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build/cmake --config Release
```

MinGW Makefiles на Windows может не работать в каталогах с кириллицей.
Основной `python scripts/build_cpp.py` использует относительные пути и работает в текущем каталоге.
Для CMake с MinGW также проверена сборка с коротким ASCII-именем Windows-каталога (8.3).
Если такие имена отключены, используйте основной скрипт либо каталог с ASCII-путём.

## Структура и дальнейшая работа

- `cpp/src/`, `cpp/include/`: рабочие исходники C++.
- `generate_task.py`: единый генератор; `cpp/generate_task.py` — совместимая точка входа.
- `scripts/parse_vasekin.py`, `scripts/check_solve.py`: Python-разбор, преобразование и проверка.
- `scripts/build_cpp.py`, `scripts/solve_cpp.py`: сборка и интерфейс решателя для общего проекта.
- `scripts/run_tests.py`, `scripts/run_teacher_tests.py`: воспроизводимое тестирование.
- [reports/TEST_REPORT.md](reports/TEST_REPORT.md): результаты текущей интеграции.
- [docs/PLAN.md](docs/PLAN.md): первоначальный план, сохранённый для истории.

Распределённый запуск, универсальное сравнение произвольных алгоритмов и оркестратор из исходного плана пока не реализованы.
